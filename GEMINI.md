# Horse and Rider's Companion — Project Instructions

## Git Workflow

After completing an implementation:

1. Run the relevant tests and verify the changes work.
2. Review `git status` and `git diff`.
3. Stage only files related to the completed task.
4. Create a local Git commit with a clear, descriptive commit message explaining what changed.
5. Verify the commit succeeded and report its short hash.
6. Leave unrelated changes untouched.

### Rules
- Automatically stage and commit completed, tested work locally without asking each time.
- Never push to GitHub unless explicitly requested by the user.
- Never deploy to Firebase or modify production without explicit approval from the user.
- Never commit credentials, secrets, generated build files, or temporary debugging files.
- If tests fail or changes are incomplete, report the problem rather than committing broken work.
- Do not amend or rewrite existing commits unless requested.
